## Overview

Gitstack is my ongoing attempt to rethink the foundations of how developers collaborate, version code, and build software together. It’s an open-source Git platform, but the ambition goes far beyond just hosting repositories — Gitstack is designed to be the **next evolution of developer infrastructure**, where version control becomes programmable, composable, and deeply integrated into modern development pipelines.

While tools like GitHub and GitLab revolutionized how we share code, their core workflows haven’t changed much in over a decade. Gitstack exists to challenge that. I want to build a platform that feels more like an *operating system for source code* — where you can build apps and automations around Git itself, plug into AI agents, orchestrate complex deployment flows, and even interact with Git repositories from the CLI, the web, or APIs in ways that go far beyond the traditional push-and-pull.

## Authentication and the CLI

A major part of Gitstack’s developer experience is the command-line interface. I want the CLI to feel as intuitive and seamless as any native tool — lightweight, powerful, and deeply integrated into your workflow.

One piece of this puzzle is **authentication**, which Gitstack approaches in a modern way. Instead of clunky token-based flows or requiring users to manually copy keys around, the CLI can initiate a browser-based login flow and wait for authentication to complete, just like you see in tools like Vercel or Supabase. Here’s an example of a simple helper that illustrates the idea:

```python
def wait_for_auth(timeout=120):
    """Wait for the browser to complete authentication."""
    start_time = datetime.now()
    click.echo(f"Waiting for authentication to complete (timeout: {timeout}s)...")
```
This is just a small piece of the system, but it shows the direction Gitstack is heading — towards developer experiences that feel modern and effortless without sacrificing power.
