I never really got rejection letters (seriously, never). I either get the job or get ghosted. So I'm leaving this here for myself and anyone who finds it helpful. For software engineers and AI engineers who want to stand out. It doesn’t have to be this intense, I just love the thrill of hard things, but this will get you the job easier.

## High-Level Rules (Read Once, Obey Forever)

*   **June 1, 2023:** Set the baseline for consistent practice.
*   **Daily minimum:** 60–120 min focused practice. Shorter is OK if laser-focused.
*   **Always timebox with a timer:** Pressure practice leads to real interviews feeling easier.
*   **Track per session:** Focus on correctness, time-to-solve, and explainability (<90s).
*   **Keep a scoreboard doc:** Record the question, date, time, result, and notes. Iterate.

## Daily Template (60–120 min)

*   **Warm-up (10–15 min):** Solve 2 easy coding problems for speed.
*   **Deep practice (30–60 min):** Tackle 1 medium/hard problem or research experiment. Write code/notebook.
*   **Math/derivation (15–20 min):** Complete 1 short derivation (e.g., softmax gradient, SVD).
*   **Behavioral (10–15 min):** Practice 1 STAR answer aloud (record or role-play).
*   **Debrief (5–10 min):** Update scoreboard and note one improvement.

## Progression (Easy → Hard)

### A. Coding

*   **Easy:** Balanced brackets stream, stable softmax + cross-entropy, palindrome, count islands.
*   **Medium:** LRU cache (O(1)), sliding-window median/longest unique substring, BFS variants.
*   **Hard:** DP (knapsack, edit distance), graph (topo sort + SCC), mini trainer loop with stability.

### B. Math & ML Theory

*   **Easy:** Softmax → cross-entropy gradient, subtract max from logits.
*   **Medium:** Backprop single attention head, chain rule small network.
*   **Hard:** SVD rank-k approximation proof sketch, Adam equations + stability trade-offs.

### C. Systems / Design

*   **Easy:** Logging schema for LLM inference.
*   **Medium:** Minimal middleware (API, hooks, latency, telemetry).
*   **Hard:** Scale model-agnostic inference filter to 1M daily requests—reliability, monitoring, cost, A/B, rollback.

### D. Research & Experiments

*   **Easy:** Recent paper claim → 3-step reproducibility plan.
*   **Medium:** Tokenizer comparison on perplexity (controls + stats).
*   **Hard:** 3-day instability detector plan—dataset, metrics, baselines, ablations, failure modes.

### E. Behavioral & Fit

*   **30–60s pitches:** Intro, top project, research question.
*   **STAR:** Leadership, failure, trade-offs, fast learning, collaboration.
*   **Tough:** “Biggest mistake?”, “Zero data decision.”

## Concrete Question Bank

*   **Coding easy:** Balanced brackets stream, stable softmax.
*   **Coding medium:** LRU cache O(1), sliding-window max/median.
*   **Coding hard:** Edit distance O(n) space, top-k stream sequences.
*   **Math easy:** Cross-entropy gradient.
*   **Math medium:** PCA = top eigenvectors.
*   **Math hard:** SVD rank-k proof sketch.
*   **Systems medium:** Middleware 2000 req/s, <200ms p95.
*   **Research medium:** Paraphrase attack robustness experiment.
*   **Behavioral typical:** End-to-end ownership, technical disagreement.
*   **Behavioral harsh:** Biggest failure, why you over PhD + 5yr top lab.

## Mock Starters

*   **Coding:** “Implement is_balanced(stream) for brackets. Think aloud, target complexity.”
*   **Research:** “Design experiment: does LoRA preserve calibration? Dataset, metric, baseline, ablation.”
*   **System:** “Design inference-time instability filter <2× latency. Draw architecture, failure modes.”

## Scoring Rubric (Post-Mock)

*   Correctness 0–5
*   Time 0–5
*   Tests 0–5
*   Explainability 0–5
*   Confidence 0–3

## Weekly Targets

*   **Week 0:** Easy coding 10–18 min, softmax gradient <6 min.
*   **Week 1:** Medium 30–45 min, solid system sketch 20 min.
*   **Week 2:** Hard coding partially correct, full research plan with ablations.
*   **Week 3:** 3 full mocks ≥4 on Correctness & Explainability.

## Interview-Day Tactics

*   30s pitch first, state strength.
*   Coding: outline → complexity → code.
*   Math: write steps, narrate; stuck → propose experiment.
*   Systems: draw fast, annotate failures/metrics, high-level then drill.
*   Don’t know: “I’d measure it like this” + experiment.

Should be easy if you've got heart and spine.
